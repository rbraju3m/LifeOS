# 12. API Specification (v1)

### 12.1 Conventions
- **Base:** `/api/v1`. JSON only, `Accept: application/json`. Versioning goes in the URL path. Breaking changes require `/v2`; additive changes are allowed in v1. Deprecations are announced with the `Deprecation` and `Sunset` headers.
- **Auth:** Sanctum session cookie, plus the `X-XSRF-TOKEN` header for state-changing requests. "Auth" below means authenticated with a verified-or-grace user. "V" means a verified email is required.
- **IDs:** ULID strings (lower-case, as generated by Laravel `HasUlids`). Unknown IDs and IDs the caller is not allowed to see both return **404** (to avoid leaking existence). A known resource the caller can see but not modify returns **403**.
- **Success envelope:** `{ "data": {...} }`. Lists: `{ "data": [...], "meta": { "next_cursor": "...", "per_page": 25 }, "links": { "next": "..." } }`.
- **Errors (RFC 9457 problem+json):** `{ "type": "https://lifeos.example/errors/validation", "title": "...", "status": 422, "code": "validation_failed", "detail": "...", "errors": { "field": ["message"] }, "request_id": "..." }`. Messages are localised by the user locale.
  - Codes: 400 bad_request, 401 unauthenticated, 403 forbidden, 404 not_found, 409 conflict (version/idempotency mismatch), 413 payload_too_large, 415 unsupported_media_type, 419 csrf_mismatch, 422 validation_failed, 423 account_locked, 429 rate_limited (with `Retry-After`), 402-like `entitlement_exceeded` returned as **403** with `code: entitlement_exceeded` and `meta.feature`.
- **Pagination:** cursor-based (`?cursor=&per_page=` default 25, max 100), ordered by a stable key ending with `id`.
- **Filtering:** `filter[status]=open&filter[list_id]=...&filter[tag]=...&filter[due_from]=2026-11-01`.
- **Sorting:** `sort=-due_at,priority`, with a whitelisted set of fields per resource.
- **Search:** `q=` (min 2 chars).
- **Idempotency:** POST create endpoints accept an `Idempotency-Key` header (UUID/ULID, 24 h, per user). Replaying the same key with the same body returns the stored response with `Idempotent-Replayed: true`; replaying with a different body returns 409 `idempotency_key_reused`; a repeat while the first is still running returns 409 `idempotency_request_in_progress`; a malformed key returns 400 `idempotency_key_invalid`. Only 2xx responses are stored.
- **Concurrency:** resources return `updated_at` and `version` (`updated_at` in epoch milliseconds). PATCH accepts `If-Match: <version>` (bare, quoted or weak ETag form); a stale version returns 409 `version_conflict` with `meta.current_version`. Without `If-Match` the update is applied (last write wins).
- **Dates:** instants are ISO 8601 UTC (`2026-11-18T03:00:00.000Z`) **plus** the `timezone` field. Date-only values are `YYYY-MM-DD`.
- **Rate limits (per user unless noted):**

| Limiter | Limit |
|---|---|
| `auth` (per IP + email) | 5/min, then lockout escalation |
| `register` (per IP) | 10/hour |
| `password-reset` (per email) | 3/hour |
| `api` | 120/min |
| `writes` | 60/min |
| `uploads` | 20/hour |
| `export` | 1/24 h |
| `search` | 30/min |
| `invite` (Phase 5) | 20/day |

### 12.2 Endpoints — Identity & session (Fortify routes, under `/api/v1/auth`)

| Method | URL | Purpose | Authz | Request / validation | Response | Rate |
|---|---|---|---|---|---|---|
| GET | `/sanctum/csrf-cookie` | issue XSRF cookie | public | – | 204 | api |
| POST | `/auth/register` | create account + default prefs + consents (personal space + free plan added in slice 1.2); does **not** sign in | guest | name req 2–120; email req email:rfc (+dns in production), **no unique rule**; password req min 10, max 128, uncompromised, confirmed (no composition rules, NIST-style); locale in:bn,en; timezone IANA; accept_terms accepted; unknown fields rejected | **202 `{message}` — identical whether or not the email already exists** (existing owner is emailed instead) | register |
| POST | `/auth/login` | start session | guest | email, password, remember bool | 200 user or `{two_factor:true}` | auth |
| POST | `/auth/two-factor-challenge` | 2FA step | pending-login session | code 6 digits or recovery_code | 200 user | auth |
| POST | `/auth/logout` | end session | Auth | – | 204 | api |
| POST | `/auth/forgot-password` | send reset link | guest | email | 202 (always, no user enumeration) | password-reset |
| POST | `/auth/reset-password` | reset | guest | token, email, password rules | 200 | password-reset |
| POST | `/auth/email/verification-notification` | resend verification | Auth | – | 202 | 3/hour |

| POST | `/auth/user/confirm-password` | step-up for sensitive actions (valid 15 min) | Auth | password | 201 (Fortify); routes that need it answer **423 `password_confirmation_required`** until confirmed | auth |
| POST/DELETE | `/auth/user/two-factor-authentication` | enable/disable 2FA | Auth + confirmed pwd | – | 200 qr+secret / 204 | api |
| POST | `/auth/user/confirmed-two-factor-authentication` | confirm 2FA | Auth | code | 204 | auth |

| PUT | `/auth/user/password` | change password (logs out other sessions) | Auth | current_password, password | 204 | auth |
| POST | `/auth/sessions/logout-others` | revoke other sessions | Auth + confirmed pwd | – | 204 | api |

### 12.5 Content resources (all space-scoped: `/spaces/{space}/…`)
The same pattern applies to every content resource:
- `GET` list (filters/sort/cursor), `POST` create (idempotent), `GET /{id}`, `PATCH /{id}` (If-Match), `DELETE /{id}` (soft), `POST /{id}/restore`, `DELETE /{id}/force` (from Trash only).
- **Authorization:** see the matrix in §14. Every request runs `SpacePolicy::access(space)` → role ability → item visibility.

| Resource | Extra endpoints | Key validation |
|---|---|---|
| `task-lists` | `POST /{id}/archive` | name 1–100; color hex |
| `tasks` | `POST /{id}/complete` (returns next instance if recurring), `POST /{id}/reopen`, `POST /reorder` | title 1–255; description ≤10k; due_date date; due_time H:i requires due_date; timezone valid; rrule parseable, FREQ in DAILY/WEEKLY/MONTHLY/YEARLY, COUNT ≤ 1000, min interval daily; priority 0–3; task_list_id in same space; tag_ids in same space; assignee active member (Phase 5); reminders[] inline (max 5) |
| `events` | `GET ?from&to` expands occurrences; `PATCH /{id}/occurrences/{originalStart}` (scope=this\|following\|all); `DELETE /{id}/occurrences/{originalStart}` | title 1–255; all_day bool; starts_at < ends_at; duration ≤ 14 days for timed; rrule rules as tasks |
| `important-dates` | – | kind enum; month 1–12; day valid for month; year 1900–current |
| `notes` | `POST /{id}/pin`, `/unpin`, `/archive`; `POST /{id}/attachments` (file_id); `DELETE /{id}/attachments/{file}` | body ≤100k chars |
| `records` | `POST /{id}/reveal` (returns decrypted reference_number + fields; audited; requires recent auth ≤ 15 min); attachments as notes; `GET /record-types` | record_type enum; reference_number ≤ 100; expiry_date ≥ issue_date; fields ≤ 20, label ≤ 100, value ≤ 1000 |
| `tags` | – | name 1–50 unique per space |
| `reminders` | `POST /{id}/pause`, `/resume`; `GET /{id}/occurrences` | trigger_kind; absolute: remind_at_local in future (allow ≤1 min past); relative: source required, offset −525600..0; channels ⊆ entitled channels; max 10 active per source, 500 active per user on Free |
| `files` | `POST` multipart upload (`file`), `GET /{id}` metadata, `GET /{id}/download-url` → `{url, expires_at}` | size ≤ `files.max_upload_bytes`; detected MIME in allow-list; quota check `storage.max_bytes` |

### 12.7 Health
`GET /up` (Laravel liveness, no dependencies) and `GET /health/ready` (DB, Redis, storage, scheduler heartbeat < 3 min, queue backlog). The second is IP-restricted or uses a token, and returns no internal details publicly.

### 12.8 OpenAPI
Scramble generates `docs/openapi/v1.yaml`. CI fails if the committed spec differs from the generated one (`spec:check`). The frontend runs `npm run gen:api`, which uses openapi-typescript to produce `src/api/schema.d.ts`.
Example (abridged):
```yaml
/api/v1/spaces/{space}/tasks:
  post:
    security: [{ sanctumCookie: [] }]
    parameters: [{ name: space, in: path, required: true, schema: { type: string, pattern: '^[0-9A-HJKMNP-TV-Z]{26}$' } },
                 { name: Idempotency-Key, in: header, schema: { type: string } }]
    requestBody: { content: { application/json: { schema: { $ref: '#/components/schemas/TaskCreate' } } } }
    responses:
      '201': { content: { application/json: { schema: { properties: { data: { $ref: '#/components/schemas/Task' } } } } } }
      '403': { $ref: '#/components/responses/Forbidden' }
      '404': { $ref: '#/components/responses/NotFound' }
      '422': { $ref: '#/components/responses/ValidationFailed' }
      '429': { $ref: '#/components/responses/RateLimited' }
```
